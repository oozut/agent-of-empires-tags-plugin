# M0 — prove a header on a real session

Gate for everything else. No UI, no second harness, no cost display. Everything in this file is
M0-scoped; parameters it introduces are also in `parameters.md`.

## Preconditions

| # | Precondition | Blocks | If missing |
|---|---|---|---|
| 0 | The host aoe supports the manifest schema in `parameters.md` §1 (17 = aoe ≥1.20.0; 18 needs ≥1.21.0) | M0-T01 install | **satisfied**: host verified at aoe 1.21.0 on 2026-10-29, and the manifest stays at 17 for M0 because no M0 task uses a schema-18 feature — the 18 + `aoe_version` bump lands with M1-T03 |
| 1 | A consumer system on the real request path that records request headers, and a way to read it (open decision #4) | acceptance 5 (second proof) | do acceptance 5 locally with the sink and mark the consumer half `pending`; do not fake it |
| 2 | The sandbox substrate reachable by the daemon user (container runtime access, harness wrapper credentials) | acceptance 2, 3 | record as precondition failure; prove only the minting half, adapter row stays `documented` |
| 3 | `aoe` binary resolvable from a hook shell (`command -v aoe`) | `AOE_BIN` resolution | `setup --print` fails loudly, `doctor` explains |
| 4 | A harness whose header capability is known (first row: pi) | everything | see `docs/harness-adapters.md` offline research |

## Tasks

Priorities: `P0` blocks the acceptance below, `P1` is needed to use the milestone for real (or by
the next one), `P2` may slip. Legend: `plan/README.md`.

The numbered list is the *detail*; the task table below it is the *index* (ID, priority, lane,
dependencies, size, output). Number and ID must agree — if a task is added, append it to both.

1. **[P0] Scaffold.** `aoe-plugin.toml` (§1 of `parameters.md`), `README.md`, `.gitignore`,
   `.aoe-build/` reserved. `cookiecutter gh:agent-of-empires/plugin-template` is the reference
   layout, not a dependency. Install with `aoe plugin install ./`.
2. **[P0] CLI core.** `bin/aoe-llm-tags` with `hook`, `value`, `doctor`, `setup --print`, `verify`
   (stub in M0). One resolver module, no aoe imports, stdlib only.
   - Resolution order: row via `aoe session show` (2 s) → flags → defaults.
   - Settings from the effective config, missing section = empty, malformed TOML = warn on
     stderr + exit 0.
   - Render every enabled header; print one `NAME=value` per line.
3. **[P0] Resolver tests** (`tests/`, no aoe needed): accumulate/dedupe/cap, grammar rejection,
   `short_id`, template fields incl. missing ones, env-name derivation, disabled headers emit
   nothing, empty settings, malformed TOML. These gate the two values acceptance 4 and 7 check.
4. **[P1] Doctor tests:** classification against a temp app dir, one case per breakable check.
5. **[P0] `setup --print`.** Emits both hook lines (same command) + one mapping line per enabled
   header for the adapter, and nothing else. It resolves the `aoe` path once and writes it into
   the line.
6. **[P0] Install the hook.** Paste both lines into `<app_dir>/config.toml` (global). Confirm
   with `aoe session show` from a session shell that the variables are present.
7. **[P0] Static mapping.** Create the harness config (pi: `~/.pi/agent/models.json`,
   `providers.<id>.headers`, keeping a non-empty `models` list) — create, don't patch an absent
   file; back up if present.
8. **[P0] Sink run** (mechanism leg): `tools/header-sink.py` on `127.0.0.1:8787`, isolated
   harness config, one request from inside a session, header in `/tmp/tag-sink.jsonl`.
9. **[P0] Consumer run** (real path): same session through its normal launcher, header visible at
   the consumer. Record the hop and the query used in `docs/reference-deployment.md`.
10. **[P1] Second enabled header.** Turn on the discrete session header, confirm it arrives
    independently (acceptance 4). The plugin must work with one header; the contract says it also
    works with several.
11. **[P0] `doctor`.** Every check in `docs/implementation.md` §Step 5, absolute paths, exit 1 on
    failure. Deliberately break each of: `before_session`, `before_start`, command path, mapping,
    `AOE_BIN` — confirm the message names the broken one.
12. **[P1] Docs page.** `docs/install.md`: paste these lines, run this, expect this. Three
    commands maximum before the first success signal.

## Acceptance → evidence

| # | Check | Evidence |
|---|---|---|
| 1 | terminal + structured sessions both send the header | two sink lines, session ids differ, same tool |

| 3 | restart keeps the value, picks up an edit made before, ignores one made after | three values in one log, with the restart timestamps |
| 4 | feature + session tokens present; second header independent | the sink line for each enabled header |
| 5 | two proofs: sink + consumer | sink line + consumer record (query in reference-deployment) |

| 7 | no hook ⇒ no header, nothing breaks | session starts, `env` shows no tag variable, doctor says unwired |

## Done when

- Every P0 task is complete; P1 tasks may follow within the same release but must be listed as
  open in `plan/README.md`.
- `doctor` exits 0 with both keys present on a clean install, and exits 1 naming the broken
  component for each of the five deliberate breaks.
- One sink line and one consumer record exist for the same session id.
- Acceptance 2/3 are either green or documented as a precondition failure with the minting half
  proven.

## Risks

- **Consumer-side reality.** If the first hop strips unknown headers, the fix is consumer config,
  not plugin code. Find out in step 8 before building any UI.
- **Over-fitting the harness.** The pi wrapper on this host regenerates config; that fact belongs
  in the adapter row and `reference-deployment.md`, never in the resolver.
- **Empty-value semantics** (open #9): decide before step 2 lands, because it changes what the
  hook prints and what `doctor` calls wired.
