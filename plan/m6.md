# M6 — activity families

The gap this closes: M5 made the activity real — a badge, a pane, a page, a skill and a
per-request delivery — but with **nine words compiled into the binary**. `test` meant exactly one
thing on every machine, and the sentence that says *when* to move into a word did not exist at
all: the mapping lived in a table in the skill, and nothing in the model said what "reviewing"
requires. Meanwhile a user who wanted `write`, `measure` or `triage` had no route except a patch,
and a repository had no way to say "these sessions start in *this* vocabulary".

This milestone makes the vocabulary data:

- A **family** is a named set of activities. Each activity has a label, a lucide icon, a tone, and
  a `when` sentence — the transition requirement in prose ("when starting to implement the
  feature, move the activity to coding").
- Definitions come from four places, each replacing a same-named family whole: the built-in
  `default`, the plugin settings (global or profile), the project's settings, and a TOML file
  inside the repository — **the repository wins a conflict**.
- The family a session starts in is a **per-project** setting, so a repository's sessions begin in
  the vocabulary that repository works in.
- A session **pins** its family at launch (`sessions/<id>/activity.toml`). Editing a family, or the
  choice, therefore applies to the *next* session and never relabels a running one; only the
  current value changes while a session runs.

`when` is advisory in this milestone. A heuristic that moves the activity by itself is still
refused (`plan/parameters.md` §5b, "Who sets it"): an inferred activity is a guess sent downstream
as a claim about the session. The sentence is modelled and rendered now so that a future
machine-readable trigger can join it without changing the file shape — that is the whole reason it
is stored rather than described in the docs.

## Tasks

Priorities: `P0` blocks the acceptance below, `P1` is needed to use the milestone for real (or by
the next one), `P2` may slip. Legend: `plan/README.md`.

The numbered list is the *detail*; the task table below it is the *index* (ID, priority, lane,
dependencies, size, output). Number and ID must agree.

1. **[P0] The model.** `src/activity.rs` stops being a table of nine constants and becomes
   `Activity { key, label, icon, tone, when }` and `Family { name, activities }`, plus
   `Families { list, chosen, source, warnings }`. Validation is data-shaped: a key is lowercase
   kebab (it is a tag value), an icon is a lucide kebab name, a tone is one of five, `when` is a
   sentence capped at 400 characters, a family name is letters/digits/`.`/`_`/`-`. `find` accepts
   the key, `activity:<key>`, any case, and the label (an agent quoting the badge), and always
   stores the key. The built-in `default` family keeps the nine words and gains their `when`
   sentences, so nothing that worked before changes.
2. **[P0] One precedence order, in one function.** `activity::resolve(&Settings)` folds built-in →
   settings rows → repo file, replacing a same-named family whole, and picks the starting family
   from the repo file's `default`, then `activity_family`, then `default`. Every surface calls it;
   no surface re-derives an order. An unknown choice is a warning and the built-in family.
3. **[P0] The settings and the manifest.** `activity_family` and `activity_families` are declared
   `per_project` in `aoe-plugin.toml` (an `object_list` of `{family, value, label, icon, tone,
   when}`, so the project form can edit rows) beside a non-per-project `activity_file`. The resolver
   parses all three once, so the hook, the CLI and the worker read one shape.
4. **[P0] The repository's file.** `activity_file` (default `.aoe/activity.toml`, empty = off),
   read with the same safety as `tags_file` — relative to the project, cannot leave it, a symlink's
   canonical target is checked, ≤64 KiB, capped on the read — but **missing is silent**, because a
   repository that declares no families is not a problem. Failure is a warning and no families,
   never a failed launch. Two accepted shapes: `[families.work.activities.code]` written by hand,
   and the flat `[[activities]]` rows the settings UI and the pin use.
5. **[P0] Launch-scoped pinning.** The hook writes the resolved family to
   `sessions/<id>/activity.toml`; the `activity` verb and the pane read the pin and fall
   back to the live resolution when there is none. A launch that resolved nothing but the built-in
   writes no pin, so "a launch that carries nothing writes nothing" stays true.
6. **[P1] Per project.** `activity_family` and `activity_families` are `per_project`. The worker
   reads them with `config.get {key, project_path}` beside `feature_tag`; the hook — which runs in
   a bare shell with no host RPC — reads `projects.json` (global, then the profile's, which
   shadows it) and folds the same keys into the same settings table. Both paths produce one
   settings table, so a value means the same thing whichever read it.
7. **[P1] The command.** `activity <word>` validates against *this session's* family and names it
   when it refuses; `activity --show` prints the family, where it came from and the words it
   allows; `--json` carries `family`, `source` and the `vocabulary` array with `when`.
8. **[P1] The surface.** The pane's Activity section offers one row per word in the *selected
   session's* family, marks the current one, and names the family, its source and the other
   families defined on the machine. It spells no icon or word of its own: it renders what the
   worker payload carries. The tags are edited here and not on the page (§"Where it is edited"),
   so there is one place to look and no second vocabulary to keep in step.
9. **[P1] The carriers discover, they do not assume.** The `aoe-activity` skill and the always-loaded
   reminder stop listing nine words as *the* vocabulary: they run `activity --show` first, work from
   the family it prints, and quote `when` as the rule to follow. Both files change, so
   `DISCLOSURE_VERSION` moves to 5 and the two pinned digests in `tests/extension.rs` move with it.
   Every existing receipt is invalidated, which is what the digest pin is for.
10. **[P1] The docs.** `plan/parameters.md` §5b stops describing a globally closed vocabulary and
    states the precedence order, the pin and the advisory nature of `when`; the README and the
    manifest's help text say the same in a user's words.
11. **[P1] `doctor` answers "what does this session allow?".** One `activity family` check: `ok`
    with the family, its source and its words; `warn` naming the file when it could not be read.
    Without it the vocabulary is only visible from inside a session, which is exactly where a
    misconfiguration is hardest to see.
12. **[P2] A machine-readable trigger.** A `trigger` key beside `when` (a closed predicate set:
    `tag:<key>`, `git.<fact>=<value>`) that the `activity` verb enforces and the pane can grey out
    unreachable moves. Deliberately not in this milestone: the prose has to be right first, and an
    enforced predicate that a user cannot satisfy is worse than a sentence.
13. **[P2] Authoring from the pane.** The settings UI already edits `activity_families` rows (the
    plugin's settings form is fed by the manifest's `object_list` fields). What is missing is a pane
    action, "define a family for this project", that writes the project's registry entry — the page
    carries no editor, so the pane is where it belongs. The project form is the route today.

## Acceptance

1. **A user replaces the vocabulary without a patch.** `activity_families` rows (settings UI or the
   settings table) define a family; `activity_family` selects it; `activity --show` in a new
   session prints that family and `activity <one of its words>` works. A word from the old
   vocabulary that the new family does not define is refused with exit 2, and the message names the
   words that do exist.
2. **The repository wins a conflict, and a conflict is legible.** A `.aoe/activity.toml` naming a
   family that the settings also define replaces that family *whole* — the settings' extra rows are
   not merged in, so a reader never has to reason about a half-and-half family. Families the repo
   does not name still come from the settings, and the built-in `default` survives unless a source
   overrides it.
3. **`when` is stored, rendered and honoured by the agent.** `activity --json` carries it, the pane
   show it, the skill tells the agent to follow it, and nothing in the plugin acts on
   it: no code path infers a transition. The sentence survives the round trip through the pin
   (including quotes and newlines) byte for byte.
4. **Editing applies to the next session, not the running one.** With a session launched and
   `activity.toml` rewritten on disk afterwards, the running session's `activity --show`,
   `activity <word>`, the pane rows still use the pinned family. A session launched
   with nothing but the built-in writes no pin at all.
5. **Per project means per project.** Two registered projects with different `activity_family`
   values start their sessions in different families; a project that sets nothing inherits the
   global value; a profile's registry entry shadows the global one; and a session with no project
   path inherits without a warning.
6. **Nothing a repository says can break a launch.** A missing file is silent; a malformed, oversized
   or escaping file, an unknown tone, a bad key and a bad family name are each a warning that names
   the file and the row, and the session still starts with the families that did resolve.
7. **The consent story stays true.** The carriers change, so `DISCLOSURE_VERSION` is 5 and both
   pinned bundle digests move with it: every earlier receipt is invalidated, which is what the pin
   exists to do.

## Done when

- T01–T05 are complete: a family defined only in the settings and a family defined only in a
  repository's `.aoe/activity.toml` each drive the badge, the pane, the CLI and the
  agent's instructions in a fresh session, and neither touches a session that is already running.
- `plan/parameters.md` §5b no longer says the vocabulary is closed globally, states the precedence
  order and the pin, and marks `when` as advisory.
- A reviewer can answer "what does this session allow?" from four places that agree —
  `activity --show`, the pinned file, `doctor`'s `activity family` line, and the pane.
