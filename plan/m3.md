# M3 — usage views

**Roadmap-gated: do not start this milestone.** Every task here reads a consumer, which decision #4
deferred on 2026-10-29 (`plan/roadmap.md` §1). The file stays as the shape of the feature, so
un-deferring is a decision plus implementation, not a redesign.

"What did this feature and this session cost", answered by the operator's consumer system.
Depends on M2 (wiring is verifiable, so a number has a known cause) **and** on a named consumer with
a read path.

## Tasks

Priorities: `P0` blocks the acceptance below, `P1` is needed to use the milestone for real (or by
the next one), `P2` may slip. Legend: `plan/README.md`.

The numbered list is the *detail*; the task table below it is the *index* (ID, priority, lane,
dependencies, size, output). Number and ID must agree — if a task is added, append it to both.

1. **[P0] Consumer adapter interface.** One query shape: window → rows keyed by tag, plus a
   capability declaration saying which dimensions the backend can actually return
   (`spend`, `requests`, `sessions`). First implementation is whatever the reference deployment
   uses (open #4); no vendor code outside that adapter.
2. **[P0] Page board** (`slot = "page"`, `llm_tags_page`): spend or request count per tag, sessions
   with no recorded spend, headers the consumer never saw. State pushed with `ui.state.set`,
   ≤64 KiB, self-contained HTML.
3. **[P0] Degrade honestly.** A consumer without a spend dimension shows wiring-only information
   and names what it cannot answer — never a zero, never an estimate.
4. **[P1] Pane cost section** for the selected session, from the same adapter, with the window
   shown.
5. **[P1] Blocks.** `sparkline` for trend, `bar` for the feature split, `table` for the
   drill-down.
6. **[P2] Richer rules + per-project tags** in the UI (priority ordering, `title_regex`, manual
   tags). The M1 acceptance already covers project tags; this is the editing comfort on top.

## Done when

- Every P0 task is complete (interface, page, honest degradation).
- The page and the consumer's own UI agree within the consumer's aggregation granularity, and the
  read path is written down in `docs/reference-deployment.md`.
- No query runs from the page without a bounded window; no request bodies are read or displayed.

## Risks

- **Numbers without provenance.** Every displayed number must name its window and source, or it
  becomes folklore that outlives the configuration that produced it.
- **Capability creep.** The adapter interface will attract per-vendor fields; keep vendor
  specifics (auth headers, tag syntax) inside the adapter implementation.
