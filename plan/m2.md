# M2 — auto-discovery and one-click wiring

Pick an agent, get the exact change proposed. Depends on M1 (settings UI to hold the choice).

## Tasks

Priorities: `P0` blocks the acceptance below, `P1` is needed to use the milestone for real (or by
the next one), `P2` may slip. Legend: `plan/README.md`.

The numbered list is the *detail*; the task table below it is the *index* (ID, priority, lane,
dependencies, size, output). Number and ID must agree — if a task is added, append it to both.

1. **[P0] Path resolution per adapter** — plugin setting override → harness env var → aoe's
   `agent_config_dir` → adapter default. Never return a directory a launcher regenerates; the
   adapter row's `config_paths` order encodes that.
2. **[P0] Classify per substrate** — `wired`, `detected-not-wired`, `sandbox-stale`, `unknown`,
   `unsupported`; all enabled headers must be mapped for `wired`. Cache by path + sha256, invalidate
   on settings change and on an out-of-band edit.
3. **[P0] Session copy, then expose it.** `setup <agent> --apply` builds
   `<app dir>/sessions/<session id>/<agent>/…` and prints the `overlay_env` line; the user's
   config is never edited (superseded 2026-11-02 — see `docs/harness-adapters.md`
   §Per-session config). Mandatory rules: atomic rename, re-read and re-parse after writing,
   and pruned once the session is gone.
4. **[P0] `undo`** — delete this session's copy (or every session's with `--all`); there is no
   backup to restore, because the original was never written. The test is that the user's file is
   byte-identical afterwards, which it is by construction.
5. **[P2] `verify [--window]`** — **roadmap-gated** (`plan/roadmap.md` §1, decision #4 deferred).
   One request through the harness, then look for the header at the configured consumer, writing
   the "last verification" that `doctor` reports. Nothing else in M2 depends on it: discovery,
   classification, diff/apply and `undo` are all local.
6. **[P1] Pane actions** — re-detect, apply, undo, verify; each reports the substrate it applied
   to. Without them the CLI still does everything, one command at a time.
7. **[P1] Adapter rows** for two or three more mechanisms, chosen to cover the delivery shapes:
   whole header line in one env var (`claude`), name→variable mapping (`codex`), and `{env:…}`
   interpolation in a JSON config (`opencode`). Done: four rows, each verified by a portable probe
   (`tools/probe-harness.sh`) *and* a real aoe session (`tools/probe-session.sh`). The probes also
   settled what a row may claim: `aoe_hooks` marks an agent whose config file aoe itself writes
   hooks into, and aoe refuses a launch that moves it, so such a row can only use the reference
   channel — header delivery, never a per-session copy.
8. **[P2] Capability probe (opt-in).** One run against the local sink with the candidate config,
   to turn `documented` into `verified` per user and harness version. Never in the default
   refresh. The two scripts under `tools/` are the portable form of this: a throwaway `HOME`, a
   sink, and one evidence file per agent and per session, so a harness upgrade is re-checked by
   re-running a command rather than by re-reading a research note.

## Done when

- Every P0 task is complete; pane actions and extra adapter rows may follow (P1, tracked in
  `plan/README.md`).
- No code path writes a file the user has not seen in a diff.
- `sandbox-stale` is reproducible: wire the host, start a sandbox from an unwired store, and the
  verdict says `sandbox-stale` rather than `wired`.

## Risks

- **Format coverage.** JSON/TOML/YAML edits with marker-based undo is where corrupt-config bugs
  live; treat `undo` parity as the primary test, not an extra.
- **Discovery lying.** A false `wired` is worse than `unknown`: it stops the user from looking.
  Prefer the pessimistic verdict when the check cannot be performed.
