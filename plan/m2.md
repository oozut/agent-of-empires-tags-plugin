# M2 — auto-discovery and one-click wiring

Pick an agent, get the exact change proposed. Depends on M1 (settings UI to hold the choice).

## Tasks

Priorities: `P0` blocks the acceptance below, `P1` is needed to use the milestone for real (or by
the next one), `P2` may slip. Legend: `plan/README.md`.

1. **[P0] Path resolution per adapter** — plugin setting override → harness env var → aoe's
   `agent_config_dir` → adapter default. Never return a directory a launcher regenerates; the
   adapter row's `config_paths` order encodes that.
2. **[P0] Classify per substrate** — `wired`, `detected-not-wired`, `sandbox-stale`, `unknown`,
   `unsupported`; all enabled headers must be mapped for `wired`. Cache by path + sha256, invalidate
   on settings change and on an out-of-band edit.
3. **[P0] Diff, then apply.** `setup <agent> --dry-run` renders the patch; `--yes` writes it.
   Mandatory edit rules: backup, marker, atomic rename, refuse symlinks/non-regular files,
   re-read and re-parse after writing.
4. **[P0] `undo`** — restore the backup exactly, or remove the marker block when the file was
   otherwise untouched. Byte-identical result is the test.
5. **[P0] `verify [--window]`** — one request through the harness, then look for the header at
   the configured consumer. Writes the result to plugin settings as the "last verification" that
   `doctor` reports.
6. **[P1] Pane actions** — re-detect, apply, undo, verify; each reports the substrate it applied
   to. Without them the CLI still does everything, one command at a time.
7. **[P1] Adapter rows** for two or three more mechanisms, chosen to cover the delivery shapes:
   whole header line in one env var (`claude`), name→variable mapping (`codex`), and
   `{env:…}` interpolation in a JSON config (`opencode`). Acceptance 1 needs at least one more
   row beyond M0's.
8. **[P2] Capability probe (opt-in).** One run against the local sink with the candidate config,
   to turn `documented` into `verified` per user and harness version. Never in the default
   refresh.

## Acceptance → evidence

| # | Check | Evidence |
|---|---|---|
| 1 | each supported harness reaches `wired` from a clean config, header seen consumer-side | per harness: diff applied, verify output, consumer record |
| 2 | apply twice is idempotent; `undo` restores byte-identical original | `sha256sum` before/after, twice |
| 3 | hand-edited config after apply is detected, not overwritten | drift verdict + refusal message |
| 4 | unknown harness reports `unknown`, generic env fallback, never false `wired` | verdict output |

## Done when

- Every P0 task is complete; pane actions and extra adapter rows may follow (P1, tracked in
  `plan/README.md`).
- No code path writes a file the user has not seen in a diff.
- `sandbox-stale` is reproducible: wire the host, start a sandbox from an unwired store, and the
  verdict says `sandbox-stale` rather than `wired`.

## Risks

- **Format coverage.** JSON/TOML/YAML edits with marker-based undo is where corrupt-config bugs
  live; treat `undo` parity as the primary test, not an extra.
- **Discovery lying.** A false `wired` is worse than `unknown`: it stops the user from looking.
  Prefer the pessimistic verdict when the check cannot be performed.
