# M4 — remaining harnesses and distribution

Breadth and shipping. Can start as soon as M0 proves one row; each row is independent.

## Tasks

Priorities: `P0` blocks the acceptance below, `P1` is needed to use the milestone for real (or by
the next one), `P2` may slip. Legend: `plan/README.md`.

The numbered list is the *detail*; the task table below it is the *index* (ID, priority, lane,
dependencies, size, output). Number and ID must agree — if a task is added, append it to both.

1. **[P0] Honest row statuses.** Every remaining target (`gemini`, `vibe`, `kiro`, `cline`,
   `openclaw`, plus `hermes` promoted from `needs research`) gets a row with an explicit
   `verified` / `documented` / `needs_research` / `unsupported` status and a reason. Cheap, and it
   makes the table usable immediately.
2. **[P0] Publish path**: `aoe plugin install gh:oozut/agent-of-empires-tags-plugin` must work from
   a clean profile — no local checkout, no build step on the user's machine.
3. **[P1] Adapter rows verified** — follow the research checklist in
   `docs/harness-adapters.md` for each row and stop at the first one that is honestly
   `unsupported`. Each verified row records `verified_with`.
4. **[P1] Worker as a release binary** so the plugin does not need a Python interpreter on the
   host. Same stdio protocol; keep `bin/aoe-llm-tags` runnable as a script for debugging.
5. **[P1] Versioned release**: semver tags, `aoe_version` range in the manifest, changelog entry
   per capability change (a widened grant forces user re-approval).
6. **[P2] Featured-index PR** with the source tree hash, only if claiming a reserved namespace is
   wanted (otherwise stay out of it).

## Acceptance

1. A clean profile installs from the published source, `doctor` passes, and one request reaches
   the consumer — no manual file copying.
2. Every adapter row in the table is `verified`, `documented`, `needs_research` or `unsupported`
   with a reason; none is left blank.
3. The script and the binary resolvers agree on values for the same session (one test, both
   entrypoints).
4. Upgrading a release does not change the user's settings, and a widened capability set is
   re-prompted rather than silently granted.

## Done when

- Every P0 task is complete: `aoe plugin install` from the published source works on a machine
  that has never built it, and no adapter row is blank.
- Every `verified` row has a recorded run and a `verified_with` version pair; nothing is
  `verified` on the strength of documentation alone.
